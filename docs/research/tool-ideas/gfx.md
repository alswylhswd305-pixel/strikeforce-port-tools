# Graphics-side tool ideas (خبير الرسم), 2026-11-27

Already built: gfx_bisect v2 (/workspace/sf-shared/tools/gfx_bisect.zip). It auto-compares frames against RPCS3 screenshots, draws Arabic red-box labels, has shadow/roof/haze/face/white-ground detectors and a cutscene mode, and runs a draw bisect. So a whole-frame differ exists; the ideas below go one level deeper.

Rules for all three: box-built, no GPL/RPCS3 code (behaviour described from public ISA notes and our own measurements), diagnostics only, and Saud's OK before anything runs on his PC.

## 1. Unhandled-method census (easy: hours, logging only)
- What: count every RSX method the game writes during a frame, and mark the ones the legacy D3D12 path has no handler for, or decodes but ignores. Rank them by frequency and by how many draws are active while each one is set to a non-default value.
- Catches: the whole "register we never read" class in one shot. Polygon offset (0x0A68/0x0A78/0x0A7C) behind shadow acne, fog (0x08CC-0x08D4) behind haze, 0x1D78 depth clip, 0x1738/0x173C vertex base, viewport scale/offset, and so on. The register gaps found so far each took a separate hunt; this lists them all up front.
- Build: a static table of the methods each handler covers (generated by grepping the switch cases), plus a counter in rsx_process_method behind an env var. One frame, one report. Code change: logging only.

## 2. Shader differential tester (medium-hard)
- What: capture every VP/FP microcode the game compiles, together with its real constants and a few real input vertices or fragments. Run each one two ways and compare the outputs register by register:
  - (a) our decompiled HLSL (compiled with DXC and run on WARP or the GPU),
  - (b) a small, independent reference interpreter written from the ISA semantics.
- Catches: decompiler bugs. These are the ARL a0/a1 type of bug (which fixed the scarf sheet and most faces), swizzle/write-mask errors, condition codes, saturate, half precision, KIL, texture-coordinate ops and address-register indexing. Gives the first mismatching instruction per shader.
- Build: the interpreter is the main cost, roughly a few hundred lines for the VP and FP opcode sets. The capture side can reuse the existing FP_DUMP/VP_DUMP hooks. The tester runs on the box; only the capture needs the PC.

## 3. Texture and render-target audit (medium)
- What: for every draw in one frame, record t0-t7: offset, format, remap, swizzle/linear, gamma and expand bits, and filter/address. Also record whether the bind resolved to a real texture, a stale texture from an earlier draw, a NULL SRV, or a render target, including depth at offset 0. Decode each texture on the box with our own reference decoder, save it as a PNG, and flag:
  - unsupported formats,
  - stale or NULL binds,
  - channel-order mismatches (blue tint),
  - all-white or all-black decodes (white ground, black faces),
  - post-process passes that sample depth as "far" (haze).
- Catches: the white ground, black/flat faces, blue tint, missing decals, and haze passes reading the wrong surface.
- Build: extend the TEXFMT_ALL/TEX_BINDDBG logging into a per-draw JSON, plus a Python decoder/report on the box. It can feed gfx_bisect so a culprit draw shows its textures automatically.

Suggested order: 1 first (cheapest, widest), then 3 (targets the current white-ground and face leftovers), then 2 (prevents the next decompiler bug).
